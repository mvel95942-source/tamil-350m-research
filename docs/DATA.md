# Data: what was used, what was refused, and why

Rule for the whole project: **only established releases from known organisations, with a
clear licence, and never a benchmark or test split.** A convenient dataset was rejected
whenever its provenance or licence was unclear, even when it would have been useful.

The single source of truth in code is `tamil/sources.py`. Nothing hard-codes a dataset ID
anywhere else.

---

## Pretraining corpus

Total: **927,436,918 tokens**, packed into one flat uint16 file. Language tags per document
were stored during packing (Tamil = 0, Tanglish = 1, English = 2), but that index is not part
of this snapshot, so per-language proportions are not reproduced here.

| Source | Hugging Face ID | Split / slice | Role | Licence |
|---|---|---|---|---|
| Sangraha | `ai4bharat/sangraha` | `verified/tam` | Tamil web text | CC-BY-4.0 |
| IndicCorpV2 | `ai4bharat/IndicCorpV2` | `data/ta.txt` | Tamil web text | CC0-1.0 |
| Tamil Wikipedia | `wikimedia/wikipedia` (`20231101.ta`) | train, **first 2,000 articles removed** | Tamil encyclopedic text | CC-BY-SA-3.0 |
| FineWeb-Edu | `HuggingFaceFW/fineweb-edu` | `sample-10BT` | English text | ODC-BY |
| Dakshina | `google/dakshina` | dev, romanized Tamil | Tanglish (romanized) | CC-BY-SA-4.0 |
| GitHub code (clean) | `codeparrot/github-code-clean` | 4 of 880 shards | light code support, tokenizer only | Apache-2.0 |

Held-out documents from Tamil Wikipedia, English Wikipedia and the Dakshina test split are
**blocklisted sentence by sentence** (`artifacts/blocklist.npy`, rebuilt by
`tamil/blocklist.py`). This prevents the model from memorising evaluation text.

### Corpus construction

1. Download each source through `tamil.corpus.load_rows`.
2. Normalize, filter blocked sentences, and segment text with akshara-aware handling.
3. Tokenize with the 32k tokenizer.
4. Pack into `train_tok32k.bin` with `.idx.npy` (document starts) and `.lang.npy` (language
   per document), 262,144 tokens per training step.

Packing code: `tamil/pack.py`. Tokenizer build: `kaggle/01_build_tokenizer.py` and
`tamil/tokenizer_train.py`.

## Supervised fine-tuning data

Two accepted natural sources plus one synthetic reliability set. Nothing else passed the bar.

| Source | Hugging Face ID | Slice | Licence | Notes |
|---|---|---|---|---|
| Aya | `CohereLabs/aya_dataset` | Tamil rows of `train` | Apache-2.0 | human-curated multilingual instructions |
| IndicAlign | `ai4bharat/indic-align` | Anudesh, Dolly, OpenAssistant, WikiChat | CC-BY-4.0 | Tamil column `tam_Taml`, or mixed `interactions` for Anudesh |
| Synthetic reliability set | generated in this repo | 3,889 conversations | CC0-1.0 (our own) | arithmetic, correction, instruction, uncertainty, grammar |

IndicAlign subsets do not share a schema, so each is loaded from its own parquet file. The
earlier attempt to load the whole folder produced zero Tamil rows; that bug and its fix are
recorded in `docs/FAILURES.md`.

The synthetic set is generated by `scripts/build_sft_reliability_ta.py` from verified
templates. It contains **no prompt from the frozen holdout**, and the holdout file is checked
against it by the generator. In the SFT kernel it is repeated three times to give it real
weight against the much larger natural set.

### SFT mixture as configured

- Natural conversations: capped at 40,000 after quality filtering and deduplication.
- Synthetic: 3,889 rows × 3 = 11,667 exposures.
- Quality gate: assistant answer 8–2,000 characters, at least 3 words, no URLs.
- Deduplication on the first user turn.
- Exact per-source counts are written by the kernel to `sft_data_stats.json`; the cleaned SFT
  run had not executed when this snapshot was taken, so those counts are not claimed here.

## Sources that were rejected

Full evidence table, with download counts and reasons: `reports/sft_data_search.md`.
The important categories:

| Dataset | Reason for rejection |
|---|---|
| `microsoft/Updesh_beta` | pilot inspection showed **semantic role inversion**; licence review open |
| `ai4bharat/IndicQA`, `sarvamai/mmlu-indic`, `sarvamai/gsm8k-indic`, `sarvamai/arc-challenge-indic`, `ai4bharat/indic-math-500`, `google/IndicGenBench_*` | benchmark or test splits — contamination risk |
| `HuggingFaceFW/fineweb-2`, `nvidia/Nemotron-Pretraining-*`, `AnanthZeke/oscar_tamil_clean` | pretraining corpora, not instruction data |
| `ai4bharat/IndicVoices` | speech, not text SFT |
| `Srini99/TamilQA`, `AswiN037/tamil-question-answering-dataset`, `Hemanth-thunder/tamil-madlad-400` and similar | community datasets, provenance or quality unverified |
| Many `zicsx/*`, `CryptoYogi/*`, `gradshaan/*`, `BhabhaAI/*`, `pranjalchitale/*` mirrors | unknown licence or unverified provenance |

Two "maybe" entries were not used: `ai4bharat/IndicParaphrase` and `ai4bharat/IndicWikiBio`
(CC-BY-NC-4.0, not chat data, format review incomplete).

## The frozen holdout

`eval/tamil_reliability_holdout.jsonl` — 15 cases, written before the final SFT run and kept
out of every training file:

| Category | Cases |
|---|---|
| arithmetic | 3 (addition, multiplication, division) |
| word problem | 1 |
| geometry | 1 |
| science facts | 2 |
| Tamil grammar | 2 |
| instruction following | 1 |
| error correction | 1 |
| live weather (unknowable) | 1 |
| live population (unknowable) | 1 |
| ambiguity | 1 |
| brevity | 1 |

Each case carries human-written pass criteria in Tamil. The harness records generations; it
does not claim automatic correctness. See `docs/EVALUATION.md` for the protocol and results.

## What is deliberately not in this repository

- Upstream corpora and tokenized shards (multi-gigabyte, governed by their own licences).
- Model checkpoints and optimizer states (multi-gigabyte).
- The rejected Updesh pilot file (52 MB), kept out on purpose.
- Third-party evaluation repositories cloned during earlier, unrelated work.

Everything excluded can be rebuilt from the source IDs above.
